# ESP32 Native Wake Word Detection (`wakeword_detection_esp32`)

An on-device, real-time wake word detection system running entirely on the standard ESP32 (dual-core Xtensa LX6 without vector extensions). The firmware captures audio using an **INMP441 I2S digital microphone**, extracts 40-channel MFCC features with **ESP-DSP**, and performs INT8 quantized neural network inference using **TensorFlow Lite Micro**.

---

## Key Features

- **End-to-End On-Device**: Zero cloud dependencies; audio processing and inference happen entirely locally on the ESP32.
- **Dual-Core FreeRTOS Pipeline**:
  - **Core 0**: Continuous I2S DMA audio capture and Voice Activity RMS gating into a circular history buffer.
  - **Core 1**: Sliding-window MFCC feature extraction and TensorFlow Lite Micro inference.
- **Sliding-Window Optimization**:
  - Audio clips are 1 second (16,000 samples at 16 kHz), corresponding to 49 time frames × 40 MFCC channels.
  - The window slides every **200 ms (10 frames)**: previous 39 frames are shifted in-place, and only 10 new FFT/Mel/DCT frames are computed per cycle.
  - Reduces CPU computational load by **~80%**, keeping total processing time well under 30 ms.
- **Voice Activity Gate (RMS)**: Skips inference during silence or low ambient noise to preserve CPU headroom and eliminate idle false positives.
- **Hardware Trigger**: Drives an indicator LED (GPIO 16) with non-blocking FreeRTOS timer pulses and debounce cooldown.

## What `scripts/update_model.py` Does

The [update_model.py](file:///home/paramesh/01_projects/02_esp/inmp441_wakeword_detect/scripts/update_model.py) script bridges your offline trained machine learning model and the ESP32 C++ firmware:

1. **Loads the `.tflite` Model**: Reads the binary flatbuffer file of your trained INT8 quantized wake word model.
2. **Extracts Quantization & Tensor Parameters**:
   - Inspects the input and output tensor metadata via TensorFlow Lite Interpreter.
   - Extracts input `scale` and `zero_point` (used by the firmware's audio frontend to quantize MFCC features from float to INT8).
   - Extracts output `scale` and `zero_point` (used by the firmware to dequantize the model's logits into detection probabilities).
   - Verifies the model dimensions (e.g. `[1, 49, 40]` input tensor shape and `[1, 2]` output tensor shape).
3. **Generates C Header (`main/model_data.h`)**:
   - Creates compile-time macros (`MODEL_INPUT_SCALE`, `MODEL_INPUT_ZERO_POINT`, `MODEL_OUTPUT_SCALE`, `MODEL_OUTPUT_ZERO_POINT`, etc.) so the firmware automatically synchronizes with model quantization parameters without manual edits.
   - Formats the entire `.tflite` binary into a 16-byte aligned C byte array (`alignas(16) const unsigned char g_model_data[]`) and places it directly into ESP32 Flash memory (`.rodata`), avoiding unnecessary RAM usage.
   - Exports `g_model_data_len` for initialization with TensorFlow Lite Micro's `tflite::GetModel()`.

## Audio & DSP Processing Pipeline

1. **Audio Ingestion**: 16 kHz, 16-bit mono PCM via I2S DMA.
2. **RMS Gating**: Audio RMS is checked against `MIN_SPEECH_RMS`. If background noise is below threshold, FFT & inference are bypassed.
3. **Framing & Windowing**: 30 ms frame length (480 samples), Hann window applied, zero-padded to 512 samples.
4. **Fast Fourier Transform**: 512-point real-to-complex FFT computed using optimized assembly routines from `esp-dsp` (`dsps_fft2r_fc32`).
5. **Mel Filterbank**: 40 triangular filters spanning 20 Hz to 4,000 Hz, with sparse matrix-vector multiplication.
6. **Log Compression & DCT-II**: $\log(\text{mel} + 1e-6)$ transformed by orthogonal DCT-II matrix to yield 40 MFCCs.
7. **INT8 Quantization**: Clamped and scaled to match the training quantization parameters (`quantized = round(mfcc / scale + zero_point)`).

## Step-by-Step Workflow: Setup, Build, Flash & Monitor

Follow these steps in sequential order. Notice the environment tags specifying where each action takes place:
- `[HOST PC]` — Run in your regular PC terminal (Python environment).
- `[ESP-IDF]` — Run in a terminal with the ESP-IDF toolchain activated.
- `[ESP32 HARDWARE]` — Physical interaction with the ESP32 board and microphone.

---

### Prerequisites

| Environment | Requirement | Setup Command |
| :--- | :--- | :--- |
| `[ESP-IDF]` | **ESP-IDF v5.x** toolchain | `. $HOME/esp/export.sh` |
| `[HOST PC]` | **Python 3** with `tensorflow` | `pip install tensorflow` |

---

### Step 1: Train & Port the Model `[HOST PC]`

Run this in your **regular PC terminal** with Python.

1. **Train or Obtain a Model**:
   Ensure you have an INT8 quantized `.tflite` model trained with the expected tensor shapes (`[1, 49, 40]` input, `[1, 2]` output):
   - Record training audio using [audio_recorder_esp32](https://github.com/parameshwar-A/audio_recorder_esp32).
   - Train and export the quantized model using [esp32_wakeword_trainer](https://github.com/parameshwar-A/esp32_wakeword_trainer).

2. **Port the Model to Firmware**:
   Run the model converter script pointing to your `.tflite` file:
   ```bash
   python3 scripts/update_model.py path/to/your_wakeword_model.tflite
   ```

   The script will:
   - Verify that the model is INT8 quantized and has compatible input/output tensor shapes.
   - Extract the exact input/output quantization `scale` and `zero_point`.
   - Generate `main/model_data.h` with an aligned byte array in Flash memory.

---

### Step 2: Build the Firmware `[ESP-IDF]`

Run this in an **ESP-IDF enabled terminal** on your computer:

```bash
# 1. Source ESP-IDF environment
. $HOME/esp/export.sh

# 2. Set target to standard ESP32 (only needed once or after a clean build)
idf.py set-target esp32

# 3. Compile the firmware
idf.py build
```

---

### Step 3: Flash to ESP32 `[ESP-IDF]`

Connect your ESP32 board via USB data cable and flash the compiled binary:

```bash
idf.py -p /dev/ttyUSB0 flash
```
*(Replace `/dev/ttyUSB0` with your serial device port, e.g. `/dev/ttyACM0` on Linux or `COMx` on Windows).*

---

### Step 4: Monitor Output & Test `[ESP32 HARDWARE]`

Open the serial monitor to view real-time inference latency and detection logs:

```bash
idf.py -p /dev/ttyUSB0 monitor
```

- **Test Detection**: Speak your wake word into the INMP441 microphone. When detected, the LED on **GPIO 16** blinks, and detection logs with score & latency will print to the serial monitor.
- To exit the serial monitor, press `Ctrl + ]`.
